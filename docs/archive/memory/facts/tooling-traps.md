# Harness and tooling traps (AGENTS.md traps 15, 16)

The evidence behind `AGENTS.md` traps 15 and 16. Filed 2026-09-28 from td#54 ([comment](https://github.com/helios1168/td/issues/54#issuecomment-5866766796), m2 session 01a0e728 fork 01a0e738). The pre-#54 wording is `git show b7a74c9:AGENTS.md` traps 15 and 16.

- **Trap 15.** The archived solver harness (tag `archive/pre-support-2026-09`) keyed retries on the engine's own stop reason, `extra["retryable"]`, never on the status it reported to the harness. The new pipeline has no retry harness yet, and the rule carries over to the one it gets.
- **Trap 16.** Serena resolves relative paths against the hub, not the active worktree, so work in a worktree must pass absolute paths or use Read/Edit. This holds as long as Serena is started against the hub checkout.

## Other tooling facts

- **`tests/run_all.py` has no per-test skip** (td#66, m5 session 01a0ee38 fork 01a0ee3a, 2026-09-29; checked against `tests/run_all.py` at `2949cb0`). Its `skipped` count covers only a `SLOW` module run without `TD_SLOW=1` and tests left out by `-k`. A test that returns early counts as PASS. So a data-dependent test that skips itself, like `tests/test_data.py`'s graph tests without `tl_2025_us_state.zip` (`mem:decisions/sparse-fixture-and-loader`), shows up only in the SKIP line it prints. The `rg -v '^\s*PASS '` filter in `AGENTS.md` keeps that line. This holds until the runner gains a skip status.
- **m5-studio has no state polygons** (td#78 handoff, m5 session 01a0ee3e, 2026-09-29; checked over ssh on 2026-09-30). `data/public/tl_2025_us_state.zip` is missing on m5, in its worktrees and in its hub checkout, so the fixture ZIP-graph tests in `tests/test_data.py` skip there. m5's #78 acceptance of 53 passed, 0 failed and 0 skipped did not include those tests. m2 has the file: the lander's #78 acceptance on 2026-09-30 ran them, with the same count. Until m5 gets the file, check graph-test results on m2.
- **`$TD_PY` and `$TD_REPO` are unset in a pi-subagents worktree shell on m5** (td#64 worker run ce94bf8a, m5 session 01a0ee3d, 2026-09-29). Use `/Users/Shared/sv-ntlee/td/.venv/bin/python3` directly. The curator found on 2026-10-01 that m5 sets them in its untracked `/Users/Shared/sv-ntlee/user/.zshenv`. The sandbox's `~/.zshenv` sources that file only when `$SHARED_WORKSPACE` is set, which happens in `sv` sessions, not plain SSH logins. m2's `user/` holds no such file, so neither variable is ever set on m2. `AGENTS.md` still gives the fast-suite count as "24 fast tests" (from 2026-09-28). The same worker counted 38 on 2026-09-29, and STATE commit 5dd0e1c reports 205 passing on 2026-09-30.
  - Superseded, 2026-10-02 (m5 session 01a0f177; #81 lane run 5417ff9f): m5's `td/data/public` now has `tl_2025_us_state.zip` (downloaded from census.gov on 2026-09-30, sha256 `59a22088…`, same as m2; copying from m2 would have touched the other Studio's checkout) and `tl_2025_us_zcta520.zip`. With `TD_REPO` set, `tests/run_all.py` runs the graph tests with 0 skipped. The full suite took about 54 s on m5 after #71. In a pi-subagents worktree the 51-scenario map test still SKIPs, because it looks for the ZCTA zip only beside the state file the worktree's own `data/public` provides.
  - Addition, 2026-10-02 (td#81 lane A, m5 session 01a0fd2f): on m5, export `TD_REPO` before `tests/run_all.py`. Without it the graph and map tests print SKIP lines while the summary still says 0 skipped, as the first bullet predicts.
- **The environment variables reach neither Studio's tools** (2026-09-30 and 2026-10-01, m5 session 01a0f177): `TD_PY` and `TD_REPO` were set on neither Studio and neither had a `user/.zshenv` (m5 has one since), and m5's bash tool doesn't source it. Ad-hoc scripts use `/Users/Shared/sv-ntlee/td/.venv/bin/python3` with `PYTHONPATH` at the td root. Before sv-ntlee `d6b4efa`, `/wave` gates ran checks with the system `python3`, which has no numpy; that commit fixes the gate's Python in `wave.mjs`, pushed straight to sv-ntlee `main` because `user/.zshenv` wouldn't reach a running session's gates.
- **A script under `tools/<sub>/` that imports `td` must put the repo root on `sys.path` itself** (2026-10-02, td#81 variant run, m5 session 01a0fd2f): `nohup "$TD_PY" -u tools/exp81/x.py` from the worktree root otherwise fails with `ModuleNotFoundError`, because Python puts the script's own directory on the path, not the cwd.
- **A path-escape regression test** must point its probe at absolute paths inside its own temp dir, and be checked against the unfixed code to show it really escapes (td#71, 2026-09-30).
- **pyproj changes the run's ZIP graph** when the extract doesn't cover every graph vertex, the usual case: pyproj 3.7.2 gives 19,458 edges and 3.8.0 gives 19,453, which moved 44 of 11,721 ledger rows (0.48% of m_rel) on a comb_2026-10-02 scenario at δ 0.25; both runs pass the audit. Pin pyproj wherever plans are compared (2026-10-02, m2, session 01a0fd88).
- **td runs unchanged on Python 3.12** with numpy 2.2.6, pandas 2.3.3, networkx 3.4.2 and scipy 1.16.3 or 1.18.1: 209 tests pass and the ledger is byte-identical to the hub's; pandas 3 isn't required (2026-10-02, m2, session 01a0fd88, testing Snowflake compatibility in a local macOS venv; scipy 1.15.3 and Linux untested).
