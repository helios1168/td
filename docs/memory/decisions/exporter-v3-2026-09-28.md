# Exporter v3 policy (td#61)

**Context.** td#52 S12 needs a fresh extract with the new channels, read from a file-driven
channel list (`mem:decisions/support-refactor-2026-09-25`). td#61 built exporter v3
(`export/export_instance.py`, merged 9beed30, 2026-09-28). The worker's questions were settled
by the autonomous queue without the owner, and recorded in td#61's comment for run dcc0b8a3;
they stand until the owner rules otherwise. What v3 writes: `mem:workflow/confidential-data`.

**Decisions.**
1. A channel-less extract is one channel, `national`, and keeps its conflicting-M guard.
2. Any channel label is accepted and normalised; `channels.json` lists each channel's raw
   spellings, aggregate counts and opportunity share.
3. One divisor κ, the median positive cell M over all channels; masked reps are ranked on
   total cross-channel book.
4. Optional `--rep-ids` verification stays, with an explicit `--rep-ids-channel` selector.
5. Exported graph edges and states, the derived graph hash and graph-dependent reports are
   removed; geography comes from public data in the repo (td#62).
6. Only format 3 is written; the v1/v2 golden tests are replaced by synthetic seven-channel
   tests, keeping the guard tests that still apply.

**Alternatives rejected.**
1. Rejecting channel-less input: it would discard an existing guard, and the v3 contract does
   not require rejection.
2. Fixed aliases and rejecting unknown channels: they conflict with accepting any channel value.
3. Pinning the divisor or the rep ranking to `national`, or refusing non-national input: they
   conflict with the arbitrary-channel contract.
4. Dropping `--rep-ids`: td#61 says all existing guards stay.
5. Keeping geometry in the export: td#61 moves geography to public G1, so none leaves the work
   machine.
6. Keeping v1/v2 compatibility formats: they would not exercise the new contract.

**Consequences.** A real extract has not been run through v3 yet. The loader must read format 3
(the v2 loader test was removed until #66). `--rep-ids` without `--rep-ids-channel` is an input
error.

**Status.** Settled by the autonomous queue on 2026-09-28, merged with td#61; open to the owner.
