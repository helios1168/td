# Scenario app: the user decisions behind the 2026-09-08 rebuild

The Streamlit app was rebuilt from scratch and merged into `main` at `cdc2583` (doc
`docs/APP.md`). It runs from the hub on port 8502 (`tools/app.sh`), has its own venv
`.venv-app`, never imports `td`, and drives the drivers by subprocess. Treat these as settled;
do not re-ask.

- **Bargaining both ways**: a rep-to-district Nash match restricted to kept reps, and a
  zip-level Nash split of one district among several kept reps (`td/solvers/district_split.py`,
  greedy warm start then SCIP exact; SCIP closed real districts in under 10 s).
- **A rep's territory is exactly the zips where the rep has sales** (`S_i(z) > 0`); there is no
  separate territory table. Candidates for a district are kept reps with sales in it.
- **Released reps** fold their book into `S_free` (`model.release_reps`), priced by
  `filler_capture`, default `full`. Nash value rises when reps are released, so values are not
  comparable across released sets. Unavailable is not released (CLAUDE.md trap 20).
- Review grid: k = 10, 12, ..., 20 at δ = 10%, all clip cells in parallel. Other channels share
  the layout and go up to k = 50.
- Per-zip opportunity and rep sales shares may be shown in the browser (private tailnet only).
- Invariants restated by the user: CONUS plus DC only (`geo.assert_conus` in every driver); the
  zip table is the input and output of every step; the delivered map is the clipped one, draws
  are intermediates.
- Override modes: A relabel with no rerun; B(i) moved unit locked, rest free; B(ii) plus a hold
  set. Draw ancestor via `run_draw --lock-zips`, clip ancestor via `state_splits --bounds`.
- Run names carry only kind, district count and timestamp (`clip_k18_20260908_144239`).
- Stage-2 weights are one set per chain (`e2830be`): θ, λ and `filler_capture` score reps and
  move no geometry, so clip and split take the same three the draw took. App default `full`;
  driver defaults stay `theta` so a no-flag clip stays comparable to the committed map.
