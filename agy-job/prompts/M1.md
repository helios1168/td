## Objective

Implement and test this typed standalone function in `tools/plan_realise.py`:

```python
def execute_terminal_rematch(
    G, to_district: dict, reps_order: list | None,
    *, reservation: np.ndarray | None = None,
    criterion: str = "nash", theta: float = 0.40, lam: float = 0.30,
    filler_capture: str = "theta",
    level0_assignment: dict | None = None,
    reservation_mode: str = "none",
    reservation_floor: float | None = None,
) -> dict:
```

This is the post-realisation, ZIP-grain terminal staffing/rematch core. It must use the
unchanged realised graph `G`, the supplied ZIP-to-district mapping, and
`td.channel.gain_matrix(G, to_district, reps_order, ...)` for the valuation matrix. Every
listed representative prices every listed district. There is no candidacy, release path, or
geography mutation in this function.

The reservation semantics are the accepted contract in `agy-job/contract.md` and G2's approved
memo in `agy-job/reports/G2.json`:

- no reservation means the raw gain matrix and legacy `channel.match` result;
- with reservation, value is `g - d`, eligible edges are exactly `value > 0`, and forbidden
  entries are never clipped or adjusted;
- run masked Hungarian matching and reject a Hall shortfall rather than silently accepting an
  incomplete assignment;
- `criterion="nash"` maximises `sum(log(g-d))` over eligible matched edges, while the separate
  `welfare_uncentered_terminal` is the sum of raw `g` on the same realised assignment;
- support `criterion="linear"` if the existing matching utility supports it, otherwise reject
  unsupported criteria clearly;
- rectangular inputs are explicit: extra representatives are listed in `unmatched_reps`, and
  extra districts in `unstaffed_districts`;
- preserve deterministic ordering and do not mutate `G`, `to_district`, `reps_order`, or
  `reservation`;
- report `assignment`, `value_centered`, `welfare_uncentered_terminal`,
  `welfare_uncentered_level0`, `delta_uncentered`, `delta_centered`, `reps_swapped`,
  `unmatched_reps`, and `unstaffed_districts`.

The optional `level0_assignment` is a mapping using the same district labels. Rescore it on the
same terminal realised valuation matrix to produce the level-0 baseline and deltas. If it is not
provided, report an explicit null/NaN baseline and do not silently substitute the terminal
assignment. Include useful audit metadata: `reservation_mode`, `reservation_grain="zip"`,
`clipped_edges=0`, `nonpositive_edges`, `hall_shortfall`, `epsilon_floor`, `criterion`,
representative order, and district order. Validate dimensions, finite values, duplicate labels,
unknown mapping labels, reservation shape, and invalid criterion/mode inputs with clear errors.
