# Contiguity: hypergraph framing and alternative approaches

## 1. The hypergraph framing

Session: `RESEARCH_FRAMING_2026-10-07.md: §1.7 Objective and search structure`, Rev 2 draft for annotation. Quote: "Hypergraph partitioning with connectivity of the blocks."

* What it is: vertices are ZCTAs (or any finer unit); each state is a hyperedge containing its ZCTAs; each intermediate geography (county, CBSA, CSA) is another nested hyperedge family. A map is a partition into blocks/districts.
* Reformulation: split states = cut-net; cuts = connectivity-minus-1 (lambda-1); balance = block weight in fixed interval with free block count; rule C = each block meets at most one cut state-hyperedge; M1 = each block connected in the primal planar graph with no small balanced cut.
* Claimed fix vs support master: one standard language for splits/cuts/balance/hierarchy; multilevel heuristics handling very large instances for fast incumbents; coarsening hierarchy as first-class object. Relevant because the support master's numbers are bounds only over its own family/modes, not over drawn maps (`COUNCIL_2026-10-05.md: What the council established`, findings 14-16).
* Proposed method, `§1.7 Owner (rev 2)` 5-step `hypergraph` tab: (1) literature on cut-net/lambda-1, multilevel, exact/bounds, connected partitioning; (2) keep contiguity via connected-only refinement moves, coarsen only along primal edges, repair+gate; (3) rule C/necks as per-block checkable constraints; (4) prototype on toy vs carve-first; (5) bound question.
* Stated limits: literature lacks block connectivity, necks, rule C (`§1.7`, `§2 Analogous classes`); `§1.8 One level or two`: one level suffices for incumbents with screen-restricted search, second level only for a certificate via a lemma to prove; `§4 Open`: adopt as working language? certificate wanted?
